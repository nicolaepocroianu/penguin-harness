# CI passed on every platform again

- **Date:** 2026-10-14
- **Type:** process
- **Scope:** `ci`, `server`, `web`, `landing`
- **PR:** [#PR](https://github.com/nicolaepocroianu/penguin-harness/pull/PR)

A full CI run on the fork's `main` failed on formatting, lint, a landing test, the macOS
server build, Windows-only test failures and a server suite that never finished. Each was
fixed where it went wrong; the suite that never finished is
[the module-tree check](2026-10-14-module-check-stays-flat.md).

## Details

- The server's declarations were bundled in two tsup builds instead of one. One build made
  six TypeScript programs, each holding most of the server, and ran out of heap on the
  macOS runners; each of the two builds makes two and stays near 1 GB. The emitted `.d.ts`
  files were byte-identical.
- The server test shards built `@prismshadow/penguin-plugin-sandbox-dsh`, the sandbox
  backend the server loads by default, which `server...` alone left unbuilt.
- The `test`, `test-macos` and `test-windows` jobs gained `timeout-minutes: 45`, so a suite
  that stops making progress fails in under an hour rather than at GitHub's six-hour limit.
- The landing page's Skills section listed the sixteen `waf-authoring` skills under
  Software Development.
- `sidebar.tsx` carried a raw NUL byte, which made git treat it as binary and leave it in
  CRLF; it became the `\u0000` escape (the same string at runtime) and LF. The raw control
  bytes in `domain.ts`'s display-name pattern became escapes too.
- Seven files were formatted with Prettier, and five files' repeated imports from one
  module were merged, which `pnpm lint` requires.
- Windows tests that build their folders under the 8.3-spelled temp folder of the CI runner
  (`RUNNER~1`) compared them with the server's realpath spelling: the fake clones keyed
  folders by their realpath, the run-kinds golden test normalised both spellings of its
  root, and the bench-boards test compared against the native realpath. No golden value
  changed.
